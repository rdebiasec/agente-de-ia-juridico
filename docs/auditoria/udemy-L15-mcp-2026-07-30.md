## 0. Veredicto

MCP (Model Context Protocol) = “USB-C de tools”: estándar client↔server para descubrir tools/resources/prompts sin N×M wrappers.  
En este repo, `src/mcp/tools.py` **no es un servidor MCP**: son `@function_tool` de grounding (KB/expediente). Naming confuso; comportamiento correcto.  
**No** activar Hosted MCP / connectors Google-Dropbox / MCP remoto hacia datos de casos sin evaluación 1581.

---

## 1. Qué enseña el curso

### Problema
Antes: cada agent × cada tool = wrapper propio (auth, retry, schema) → N×M.  
MCP: N+M — client en el agent, server expone tools (también resources/prompts).

### 3 modos en Agents SDK
| Modo | Quién corre el client | Uso típico curso |
|---|---|---|
| Hosted MCP | OpenAI | SaaS públicos (Notion…); más hop; auth limitada |
| Local stdio | Tu máquina | Dev; server local (p.ej. node) |
| Streamable HTTP | Client en tu red | Tu server remoto / VPC; más control auth |

### Native connectors
Gmail, Calendar, Drive, Dropbox, Teams… OAuth gestionado por OpenAI.  
Si no hay connector nativo → MCP custom + OAuth/token vault a tu cargo.

### Seguridad (curso)
Autor/trust del server; versiones; `require_approval` en tools críticas; allowlist de tools; tool search / defer loading para tokens.

## 2. Traducción firma virtual

### Negocio

**Ejemplo:** “Busque en el expediente la denuncia” → `buscar_en_expediente` + anti-IDOR.
